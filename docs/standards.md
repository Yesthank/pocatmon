# 규칙

## 검증 게이트 (커밋·배포 전, 모두 종료 코드 0)
- `npm test`: 엔진·필드 테스트(`node --test`). world.test.js는 모든 맵의 형식, 건물 자리, 문 앞 통행, 워프 도착지, 입구에서 문·NPC·도구·표지판·출구까지의 도달성, 트레이너 시야, 걸음·조사·스프레이·경로 찾기를 확인한다. 데이터 무결성(18타입 모두 고양이 있음), 상성 무효, 능력치·데미지 공식, 물리/특수, 화상·보호막·급소, 랭크 ±6, 우선도·스피드, 상태이상 6종과 면역, 혼란, 풀죽음, 회복 상한·흡수·반동, 다단, PP·발버둥, 교체·강제 교체, 트레이너 다음 몬스터·경험치, 최종전 컷신 이벤트, 포획·도망 공식, 레벨업·기술 습득, 진행·파티·저장을 확인한다.
- `npm run sim`: 스타터 3종 × 80번 게임 한 판 전체 시뮬레이션. 관장별 첫 도전 승률이 30~97%를 벗어나거나, 스타터별 클리어율이 90% 미만이거나, 수련 배틀 평균이 260번을 넘으면 실패한다. 실행할 때마다 밸런스 결과 문서를 다시 쓴다.
- `npm run smoke`: 로컬 서버와 헤드리스 Chromium(390×844)으로 실행한다. 3D 경로는 타이틀 → 스타터 → 필드 인트로 → 라이벌 배틀 → 걷기 → 수풀 조우·포획 → 센터 → 상점 구매 → 메뉴(가방·파티·도감·지도) → 정상 최종전(흑화 컷신) → 엔딩 → 새로고침 후 이어하기까지 진행하고, `?2d` 경로는 라이벌 배틀의 기술·가방 패널까지 진행한다. 콘솔 오류가 0건이 아니거나 가로 넘침이 0이 아니면 실패한다.
- `js/data.js`의 수치를 바꾸면 세 게이트를 모두 다시 실행한다. 테스트만 돌리고 밸런스를 건너뛰면 안 된다.

## 구조 규칙
- 스크립트는 일반 `<script>` 전역 방식이다. ES 모듈·번들러·`import`를 쓰지 않는다. 이런 방식을 쓰면 `file://`로 열었을 때와 Pages에서 열었을 때 로드 순서가 깨진다. `index.html`의 로드 순서(three → data → engine → maps → world → sprites → sfx → stage3d → field → main)를 바꾸지 않는다.
- `js/engine.js`·`js/world.js`·`js/maps.js`는 DOM·`window`·`localStorage`를 직접 참조하지 않는다. 저장소는 `createStore(storage)`로 주입받는다. 난수는 인자로 받는다(`rng`). 이 규칙을 어기면 Node 테스트와 시뮬레이션이 깨진다.
- 화면(`main.js`)은 배틀 상태를 직접 수정하지 않고, `resolveTurn`이 돌려준 이벤트만 재생한다.
- `Stage`의 연출 메서드는 반드시 resolve하는 Promise를 돌려준다. reject하거나 영원히 대기하면 입력 잠금이 풀리지 않는다.
- three.js는 `vendor/three.min.js` r128 UMD로 고정한다. r160 이상에는 UMD 빌드가 없어 전역 `THREE`가 사라진다.
- 실행 중 외부 네트워크(CDN·웹폰트·API)를 쓰지 않는다. 모든 경로는 상대 경로다(Pages 하위 경로 `/pocatmon/`).

## 데이터 규칙
- 몬스터·기술의 **효과 종류**, 타입, 기술 이름, 몬스터·기술 id는 바꾸지 않는다(id는 저장 데이터에 들어 있다). 위력·명중·확률·PP·종족값·포획률·경험치·레벨·`TUNING` 값만 조정한다.
- 상성표(`CHART`)는 6세대 이후 표 그대로다. 게임 조정용으로 바꾸지 않는다.
- 저장 형식을 바꾸면 `v`와 `isValidSave`, `migrateSave`를 함께 고친다(contracts.md).
- 맵 글자는 `PMaps.LEGEND`에 있는 것만 쓰고, 건물 자리는 '#'로 채운다. NPC·도구를 문 앞이나 하나뿐인 길에 두지 않는다(world.test.js가 잡는다).
- 캐릭터 그림은 `assets/mon/<id>.webp`(768×768, 투명 배경, 발끝은 가로 중앙에서 아래 여백 3.1% 높이에 위치)이고, 이로치는 고양이 18종만 `<id>_shiny.webp`로 둔다(`Sprites` 의 `SHINY` 표와 맞춘다). 구도를 바꾸면 `Sprites.FOOT` / `Sprites.ART_TOP`도 함께 바꾼다. 함께 바꾸지 않으면 발이 뜨거나 말풍선 위치가 어긋난다.

## 커밋·배포
- `.gitignore`에 든 항목(`node_modules`, `tools/out` 등 로컬 작업 산출물)은 커밋하지 않는다.
- 저장소 상위 폴더(`files/games/pocatmon/`)의 원본 이미지는 커밋하지 않는다.
- `main`에 push하면 곧바로 공개 사이트에 반영된다. push 전에 검증 게이트 세 개를 통과시킨다.

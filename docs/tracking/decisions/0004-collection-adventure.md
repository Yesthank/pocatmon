# 0004 탐험·포획·파티 구조로 확장 (0003 대체)

**맥락.** 사용자가 게임 확장을 요청했다(2026-10-06). 상성별로 고양이를 한 마리씩 더 만들고, 전투는 실제 포켓몬 로직을 참고하며, 수집하고 바꿔 가며 낼 수 있게 해 달라는 요청이었다. 참고 자료로 smogon/pokemon-showdown, pret 디컴파일, PokeAPI가 주어졌다. 기존 v1은 5종·4연전·교체 없음·패배 시 처음부터 구조였다.

**결정.** 사용자가 고른 안은 다음과 같다(모두 추천안).
- 타입: 현대 18타입과 6세대 이후 상성표를 쓴다. 고양이가 없던 15타입에 새 고양이 15종을 만들었다.
- 구조: 지역 6곳에서 탐험·포획한 뒤 관장에게 도전하고, 정상의 수호자(메탈가디언몬 → 흑화 → 블랙)와 싸운다. 도감·보관함은 영구 저장한다. **전멸하면 센터로 돌아가 회복하고, 수집한 것은 잃지 않는다.** v1의 '패배하면 처음부터'(0003)를 대체한다.
- 전투: 핵심 규칙을 충실히 따른다. 5세대 이후 데미지, 물리/특수, PP, 상태이상 6종과 혼란, 랭크 ±6, 명중·회피, 우선도, 교체, 포획·도망 공식을 넣었다. 특성·도구·날씨는 넣지 않았다.
- 파티: 최대 3마리다(휴대폰 한 손 조작과 5~10분 단위 플레이에 맞춤).

**대안.** 로그라이크 런 확장(런 중 영입, 지면 소멸)과 수집 + 팀 대전형(탐험 없음)을 검토했다. 쇼다운 근접(특성·도구·날씨)과 6마리 파티도 검토했으나, 사용자가 고르지 않았다.

**결과.**
- 밸런스 기준이 '런 클리어율 35~95%'에서 바뀌었다. 새 기준은 관장별 첫 도전 승률 30~97%, 스타터별 클리어율 90% 이상(재도전 포함), 수련 배틀 평균 260번 이하다(`tools/sim.js`).
- 저장 형식이 `pocatmon.save` v2가 되었다. v1의 런 기록은 읽지 않는다(contracts.md).
- 쇼다운 코드는 가져오지 않았다. 공식만 참고해 `engine.js`를 새로 썼다. 원작 IP 이름이나 데이터도 쓰지 않았다. 기술 이름은 일반 명사이거나 자체 이름이고, 몬스터는 모두 오리지널이다.

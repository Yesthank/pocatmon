# 0002 3D: three.js r128 UMD를 저장소에 포함하고, 실패하면 2D로 대체

**맥락.** 링크를 텔레그램·카카오톡으로 받아 인앱 브라우저로 여는 경우가 많다. 이런 환경은 외부 CDN이 막히거나 WebGL이 꺼져 있을 수 있다. 또 빌드 없이 일반 `<script>`로만 구성하기로 했다.

**결정.** three.js r128의 `three.min.js`(UMD, 전역 `THREE`)를 `vendor/`에 넣는다. Stage는 WebGL 컨텍스트를 만들지 못하면 같은 API를 가진 2D(DOM/CSS) 구현으로 자동 전환한다.

**대안.**
- CDN 로드: 차단 환경에서 검은 화면이 되어 기각했다.
- 최신 three(r160+): UMD 빌드가 없어 ES 모듈과 import map이 필요하다. 빌드 없는 전역 스크립트 구조와 맞지 않아 기각했다.
- 3D 실패 시 오류 화면: 게임이 끝까지 진행되어야 한다는 요구에 어긋나 기각했다.

**결과.** three를 올리려면 모듈 구조로 전면 전환해야 한다. 3D와 2D 두 구현이 같은 메서드 계약을 지켜야 하므로, 연출 메서드를 추가할 때 두 곳 모두에 넣어야 한다.
